## Approach

用户明确：“机器狗之后是脱机运行，现在不过我发送提问，机器狗应该自己跑一个简单的对话程序”。经确认，脱机指**脱离电脑但机器狗可以联网**。机载 Wi-Fi 有问题，用户要求忽略，后续未改 Wi-Fi 配置或继续排障。

1. 复用现有 SSH 只读确认机载电脑 aarch64 / Python 3.8.10、内部 eth10=192.168.123.18；原厂主板音频信令 192.168.123.161:9991 TCP 可达。PC 本地云调用方案 EXP-0042 保留为调试，不作为最终部署。
2. 新增 `shared/audio/onboard_dialogue.py`：机载持有 Kimi/讯飞配置、对话上下文及扬声器音轨，提供仅回环可访问的健康、提交任务、查询任务和清空上下文接口。接受任务后后台执行，与提交连接生命周期分离；忙碌时拒绝并发，成功后保留最近 10 轮，失败不写历史。
3. PC `./go2 ask "问题"` 通过 `send_onboard_question.py` + SSH 运行机载标准库客户端 `onboard_request.py`，仅传递文字和查询结果；`--submit-only` 提交即退出，已接受任务继续处理。API Key 不经请求参数或返回值传递。
4. `async_compat.py` 及输入线程调用修正适配 Python 3.8。`run_turn` 增加无终端打印和正式回复回调供服务复用；正式回复与思考字段分离，不记录对话日志。
5. 离线部署到机载 `/home/unitree/go2-dialogue`：复制已有 2.2.0 WebRTC 驱动、ARM64 wheels、官方 Ubuntu PortAudio 用户目录库，创建 `.venv`。Ubuntu 缺 ensurepip，使用 `venv --without-pip` 加 pip 25.0.1 wheel 引导，不 apt/sudo、不改系统 Python 或导航环境。pyOpenSSL 24.2.1 / cryptography 43.0.3 / pyee 11.1.1 与 aiortc 1.9.0 固定兼容版本；补齐 Python 3.8 的 zipp 条件依赖。
6. `manage_onboard_dialogue.sh` 安装并启动 systemd 用户服务，由机载进程管理器持有，提交程序退出不停止服务。只在首个有效任务时连接内部主板音频；缺 Key 时启动仍可读取健康状态，不发云请求或扬声器请求。
