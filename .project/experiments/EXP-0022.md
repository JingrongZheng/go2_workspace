## Approach

使用已认证的 WiFi SSH 夹测机载时钟，机载端直接只读测量传感器消息头。利用同一个短时会话采集雷达 Imu 和机体 LowState 内的机体 IMU。对照此前配对点云拟合和 CMU L1 上游。


## Notes


## Results

- PC 时钟比机载约快 39 ms，最短 SSH 往返 16 ms。机载接收时间减消息头时间的中位数为 IMU 42.959 s、点云 43.025 s。估计源时间与 PC 相差约 43 s，点云多出来约 66 ms 与扫描时长同量级，不能算作两传感器同步延迟。
- 给转发增加可选的共享时间偏移。调试加 +43.0 s 后，独立录包上同一个差值指标中位为 IMU 10.2 ms、点云 87.9 ms，频率与未修正录包一致。默认零偏移，保留原本时间和逐点 time。硬件时钟未变。
- 原厂有效云坐标变换 p_base = R*p_cloud+t，t 约 [0.28216,0,0]m，RPY 约 [-167.345,-8.097,-57.899]°。剥离模型 R_y(2.8782) 后余下约 R_z(-123°)，说明发布点云的轴向还包含明显的绕 Z 旋转。拟合复现原厂点云，不等同 LiDAR→IMU 标定。
- 同时读取 1499 条雷达 IMU 与 121 条机体 IMU。静止中值加速度分别约 [4.27,0,9.81]、[0.88,0.09,9.47] m/s²。若仍假定雷达点云与 IMU 轴平行，原名义变换及实测点云变换各使重力对比相差 176.8° 和 142.0°。换点云 TF 无法修好机体翻转。一种姿态只给一个重力方向，无法唯一确定完整旋转或平移，也不能由这次检查断定传感器故障。
- CMU Go2 L1 源码对两个话题分别转换，其已处理输入及重力策略不同，未直接套入当前 Point-LIO。上游提交 43d5f54b389b251713f0097893c30fa76c870d54。

## Continuation

用户手动操控时记录至少两个独立方向的姿态变化，核对雷达 IMU 与机体 IMU 旋转、时间及静止偏置，再结合原厂点云变换求 Point-LIO 所需旋转。当前不把临时观察值写成实时外参。

2026-11-24 官方资料补查：用户给出的 L2_develope 页面未能通过网页读取工具取得正文。宇树 unilidar_sdk2 的中文 README §2 给出独立传感器坐标定义。官方 point_lio_unilidar 的 L1/L2 同为单位旋转，平移 [0.007698,0.014655,-0.00667]m，默认订阅 /unilidar/*。查看 laserMapping.cpp 的 pointBodyLidarToIMU，确认其变换方向是点坐标由 LiDAR 进 IMU 坐标。没有把独立 SDK 默认覆盖实机配置。

补齐 experiments/EXP-0022/fit_imu_rotation.py，以陀螺角速度、近似时间对齐和留出样本残差检查候选 IMU 旋转。合成的多轴旋转与 25 ms 时移恢复通过，已有静止实机记录被正确判为激励不足。实机旋转和平移仍待验证，未发运动指令。
