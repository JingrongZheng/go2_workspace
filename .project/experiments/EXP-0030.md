## Approach

针对现场建图（`.work/sessions/live-20261125-174848`）在 92 关键帧（约 `(-4.95, -1.75)`）后停止更新关键帧但 Point-LIO 实时点云仍正常移动的现象，检查配套 180 秒原始录包（`.work/sessions/bag-20261125-174857`），发现帧 1056→1057（68.62s）与帧 1282→1283（83.30s）存在 0.089 ms 与 0.226 ms 的帧间逐点时间重叠。对 `shared/dddmr/real/mapping_cloud.py` 增加微小 `/odom` 重叠跳过与 `Slerp` 时间边界夹紧，并用 `./go2 replay` 在无网络隔离容器内完整回放该 180 秒录包验证。

## Notes

本轮仅修改共享适配脚本并在无网络 Docker 中离线回放已有录包，未连接实机或发送控制指令。

## Results

- 修改 `shared/dddmr/real/mapping_cloud.py`：
  - `odom()` 中当新 `/odom` 时间戳 `<=` 上一条且回退量 `<= 0.05 s` 时跳过该样本并计数告警（`odom_overlap_skipped`），回退 `> 0.05 s` 时仍报错退出；
  - `drain()` 中对传给 `Slerp` 的 `point_times` 和 `end_time` 增加 `[0, relative[-1]]` 浮点边界 `np.clip` 防护。
- 使用 `./go2 replay .work/sessions/bag-20261125-174857 experiments/EXP-0030/replay-174857` 完整回放 180 秒录包：
  - `mapping_cloud.py` 处理全部 2772 帧输入点云，输出 2730 帧 `/dddmr/lidar_points`（39 帧 `before_lio`），全程未崩溃；
  - DDDMR 生成 **169 个关键帧**（覆盖至折返末端 `(-0.261, 1.766, -0.048)`，对比现场中断时的 92 关键帧 `(-4.949, -1.748, -0.257)` 补全了后半程 77 个关键帧）；
  - 保存服务成功，资产位于 `experiments/EXP-0030/replay-174857/maps/2026_11_25_10_09_03`：`map.pcd` 1029 点、`ground.pcd` 8066 点、`poses.pcd` 169 点、`edges.pcd` 169 条，无缺失关键帧文件。
- 实事求是说明：本次离线回放中 `odom_overlap_skipped=0`（现场 `live-20261125-174848` 未保存 `stack.log`），因此不能排除现场停图是由 `Slerp` 浮点边界、实时 DDS 调度导致的 `/odom` 重排或其它现场瞬态因素触发。
