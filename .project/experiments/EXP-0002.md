## Approach

复用 Humble 和已构建的 `unitree_ros2` 消息包。包检查和键盘控制入口位于 `experiments/EXP-0002/`。键盘节点按官方 `ros2_sport_client.cpp` 的消息格式发布 `unitree_api/msg/Request` 到 `/api/sport/request`。W/S 控制前后，A/D 控制转向，空格停止，Q 退出。首次移动输入最多等待 0.65 秒接续，连续重复后超过 0.4 秒无更新时发送 StopMove。启动后等待匹配的订阅端，收到移动键之前不发送运动指令。

## Results

三个包的路径和消息定义检查通过。伪终端验证键盘预览、空格、退出与输入超时，ROS 消息序列化往返通过。回环测试用 `ROS_LOCALHOST_ONLY=1`、Cyclone DDS 和独立域 81，本机订阅端收到了 W 对应的 Move 请求及超时后的 StopMove。验证环境中的沙箱限制了 UDP 网卡枚举，回环测试通过授权的本机执行完成。

2026-11-17 有线实机只读检查通过。PC 的 `enp2s0` 地址为 `192.168.123.222/24`，使用现有 XML 绑定网卡。三个包及消息定义校验通过，发现并收到一帧 `/sportmodestate`（`mode: 0`，`error_code: 1001`，字段语义待核对）。`/api/sport/request` 有 1 个订阅者。`/utlidar/cloud` 收到一帧点云，宽度 2195。`/frontvideostream` 收到带有非空 `video720p` 数据的消息，尚未解码。未发送控制指令。

键盘程序新增四个独立姿态键。1 为 StandUp（1004），2 为 BalanceStand（1002），3 为 StandDown（1005），4 为 Damp（1001）。伪终端预览验证了四个 API ID、按键超时停步、活动移动切换到姿态前先发 StopMove，以及姿态完成后退出不额外发 StopMove。尚未发送实机姿态指令。

用户实机观察到首次移动顺滑，停步后键盘移动卡顿，手柄仍顺滑。PC 的 GNOME 首次键盘重复延迟为 500 ms，旧脚本在 400 ms 时就发送 StopMove，有可能在长按开始时插入停步。新版给首次移动输入 650 ms，后续连续输入超时仍为 400 ms，空格即时停步。伪终端模拟 500 ms 首次重复，确认中间没有发 StopMove，后续超时仍发 StopMove。直线速度默认维持 0.20 m/s，可用 `--linear-speed 0.30` 对照宇树示例的直行速度。新版实机动作与手柄速度尚未验证。

用户报告提高直线速度后改善，转向仍偏慢。按用户要求将默认前后速度设为 0.35 m/s。A/D 转向设为 0.50 rad/s，取自宇树 Go2 Python 示例的纯转向测试值。新版数值在键盘预览核对，待实机确认。

用户实机反馈 0.50 rad/s 转向仍偏慢，A/D 提高至 0.80 rad/s。预览验证了正负转向请求，新转速待实机验证。

## Continuation

实机接线和只读收包已通过。在 PC 上加载上述两个工作空间脚本，然后执行：

```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI="file://$PWD/unitree_ros2/cyclonedds_ws/src/cyclonedds.xml"
bash experiments/EXP-0002/check_ros2.sh --robot
/usr/bin/python3 experiments/EXP-0002/keyboard_control.py --robot
```

先确认读取到运动状态。在空旷场地点按 1 并等待站稳，按需点按 2，再测试长按 W、空格、再次长按 W，确认重复起步是否改善。若仍卡顿，在相同场地对比手柄与键盘的 `/sportmodestate` 中的 `velocity`、`mode` 和 `gait_type`。可以同步读取 `/wirelesscontroller` 的摇杆输入，该话题的轴值需要与实际速度配对比较。收尾可点按 3，确认趴稳后按需点按 4，最后按 Q 退出。
