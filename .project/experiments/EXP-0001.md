## Approach

在干净的 Bash 环境中加载 Humble，保留已有源码和 DDS 配置，清除 CMake 缓存并指定系统 Python。

## Notes

旧构建的三个 CMakeCache.txt 均指定了 `/opt/miniconda3/bin/python3`。系统 Python 可加载已安装的 `python3-empy` 3.3.4。本地 `cyclonedds_ws/src/cyclonedds.xml` 为运行时配置，绑定 `enp2s0`。构建使用已安装的 Humble Cyclone DDS 0.10.5。

## Results

在 `unitree_ros2/cyclonedds_ws` 执行：

```bash
env -i HOME="$HOME" USER="$USER" PATH=/usr/bin:/bin LANG=C.UTF-8 /bin/bash --noprofile --norc -c '
source /opt/ros/humble/setup.bash &&
/usr/bin/colcon build --cmake-clean-cache --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3
'
```

退出码 0。`unitree_api`、`unitree_go` 和 `unitree_hg` 全部完成，耗时 43.7 秒。原始构建日志位于 `unitree_ros2/cyclonedds_ws/log/build_2026-11-17_18-52-07/`。

## Verification

在干净终端加载 Humble 和 `install/local_setup.bash`，三个包均能通过 `ros2 pkg prefix` 定位。完整运行 `ros2 interface show unitree_go/msg/SportModeState` 成功，并通过 `rclpy.type_support.check_for_type_support` 加载该消息的类型支持。

## Conclusion

系统 Python 和已安装的 Humble 依赖足以构建消息工作空间。本轮未测试机器狗连通性。

## Continuation

实机接线后加载本地 DDS XML，核对实际网卡名，再验证话题发现及运动状态收包。
