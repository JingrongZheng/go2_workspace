## Approach

2026-11-19 用户确认相机型号 D435i，接在机载小电脑。目标为小电脑读取 USB 深度相机，通过有线 ROS 2 传输 RGB、深度和 CameraInfo 到 PC；不走原厂 WebRTC，不消耗蜂窝数据。先确认 USB 枚举、USB 速率、现有 librealsense 与 ROS wrapper，避免直接安装不匹配的最新版。


## Notes

参考相机厂商维护的 ROS wrapper：https://github.com/realsenseai/realsense-ros 。README 提醒 Jetson 使用对应安装指南，Foxy 的部分二进制安装方式已不支持；不直接将 Humble apt 命令套到历史 Ubuntu20.04/Jetson 板端。已知版本和安装位置需板端核实后再决定。


## Results

PC lsusb 只有本机 Sonix 摄像头等设备，未发现 D435i（与接在拓展坞相符）。PC enp2s0 UP、192.168.123.222/24。有线 CycloneDDS 域 0 发现 3 秒得到现有 Go2 话题，未见 sensor_msgs/msg/Image 或 CameraInfo，也未见 RealSense 相机命名空间；不能据此断定板端未安装驱动，仅说明本次 PC 发现不到相机话题。/frontvideostream 为 Go2FrontVideoData，不能当作 D435i 深度图。

PC 命令：source /opt/ros/humble/setup.bash；source unitree_ros2/cyclonedds_ws/install/local_setup.bash；设置 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp、ROS_LOCALHOST_ONLY=0、ROS_DOMAIN_ID=0、CYCLONEDDS_URI 指向现有 enp2s0 XML；timeout 12 ros2 topic list -t --no-daemon --spin-time 3，返回 0。


## Verification


## 板端用户输出

lsusb 检测到 8086:0b3a Intel RealSense Depth Camera 435i。lsusb -t 显示设备视频接口使用 uvcvideo、HID 接口使用 usbhid，速率 5000M；确认 USB 设备枚举和 SuperSpeed 链路，不能单凭枚举断言深度流成功。

/opt/ros 包含 foxy、noetic。rs-enumerate-devices 位于 /usr/local/bin，提示存在本地 SDK 工具，版本仍待工具运行结果确认。dpkg-query 仅列出 ros-noetic-librealsense2 2.50.0、ros-noetic-realsense2-camera 2.3.2 和 description 2.3.2；不能据此认定没有源码安装的 Foxy wrapper。下一步先运行 rs-enumerate-devices，再用隔离环境加载 Foxy 并查询 realsense2_camera 包，避免混合 Noetic 与 Foxy 环境。不先安装新 SDK 或刷固件。

## SDK 枚举结果

用户 rs-enumerate-devices 输出保存 experiments/EXP-0005/device-enumeration.txt：D435I，SN 347622070300，固件 5.15.1.55，USB 类型 3.2，IMU BMI085。成功列出 Stereo/RGB/Motion 模块支持的格式；RGB8 与 Z16 深度均支持 640x360@15，另有加速度和陀螺仪。此结果确认 SDK 能访问设备并读取属性/配置，不等于实际启动连续流已通过。

下一步优先不依赖 ROS，使用已有 Python SDK 若可导入则启动该已列出的彩色+深度模式，检查实际帧与中心距离；缺少 Python 绑定不等于 C++ SDK 缺失。不升级固件或重装 SDK。

## 双视频需求与无线约束

用户明确仅需 RGB 视频和深度伪色视频。编写 shared/realsense_sender.cpp（C++ SDK，640x360@15，深度色彩范围0.2–5m）以及 PC SSH 接收录制原型 shared/record_realsense.py / .sh。SDK 官方头文件临时获取到 /tmp/go2-realsense-headers，g++ -std=c++11 -fsyntax-only 检查通过；离线 experiments/EXP-0005/check_recording.py 验证恰好两份可播放 MP4、30 对帧、颜色通道、尺寸和帧率、EOF 正常封装与截断检测通过。未部署到板端，也未验证板端开发头文件/编译器，不能宣称实机可用。

用户随后要求先停下有线方向，希望复用原厂 WebRTC 摆脱 PC 网线；明确拓展坞无可用无线，USB 网卡曾出现异常，不再将插无线网卡作为默认下一步。既有原厂 WiFi/4G 可用不等于拓展坞自身具备无线网络。

核对安装版 unitree_webrtc_connect/webrtc_video.py：客户端 video transceiver 为 recvonly，switchVideoChannel(bool) 控制既有视频，未发现把外部 USB 相机注册为原厂视频源的接口。这个客户端限制不能证明原厂服务端禁止扩展，也不能证明任意 DDS 话题都能通过原厂 WebRTC 转发。下一方向应区分媒体轨道扩展与数据通道转发：调查或用独立无害测试话题验证“拓展坞 DDS → Go2 原厂 WebRTC → PC”是否支持自定义消息，不覆盖原厂相机或运动话题。不先假定可行，也不直接否定。
