## Question

如何在不干扰导航建图（PLAN-0003）的前提下，基于 Go2 EDU 内置扬声器、内置麦克风与 WebRTC 通道，构建低延迟、可扩展的实时语音收发基础设施，并进一步支撑自然人机语音对话与多模态交互？

## Scope

- **本主线独立于 PLAN-0003**：代码收口在 `shared/audio/`（及后续 `shared/interaction/`），不修改 `shared/dddmr/`、`shared/gs3d/` 或导航/建图相关配置与实验记录。
- **阶段一（播音输出基础设施）**：讯飞开放平台「一句话复刻」训练与实时 WebSocket 流式语音合成（支持多音色别名切换与首字补偿）+ Go2 WebRTC 扬声器播放（`stream` 实时音轨 / `megaphone` / `audiohub`）与 VUI 音量控制。
- **阶段二（收音输入基础设施）**：实测 Go2 内置麦克风经 WebRTC 传回 PC 的音频采集、降噪/回声边界、VAD 断句与实时 ASR 转写。
- **阶段三（实时语音交互闭环）**：将 ASR、LLM 推理（支持流式吐字）与讯飞双向流式 TTS、Go2 实时播放串成端到端对话链路，并支持打断与状态反馈（如 VUI 灯效）。
- **安全边界**：本阶段聚焦语音与交互基础设施，**不发送任何实机运动控制指令**；所有云端 API 凭证仅存于被 `.gitignore` 忽略的 `.work/` 目录，绝不入库。

## Stop conditions

- 若实机测试发现当前 Go2 固件禁止 WebRTC 扬声器播放或麦克风采音，需先记录具体固件行为、报错与替代路径（如机载音频接口或 AudioHub 限制），不把 PC 本机播放等同于真机播音验收。
- 不将单向整句合成当成全双工低延迟对话验收；不跳过真机扬声器/麦克风实测直接宣称音频基础设施可用。

## Acceptance criteria

- **语音播报（输出）**：PC 端可通过讯飞实时流式 TTS（含复刻音色 `mambo` / `man` / `teenager`）将任意中文文本实时推送到 Go2 EDU 内置扬声器清晰发声，无首字吞音，记录实测首包延迟与可用传输通道（`stream` / `megaphone` / `audiohub`）。
- **语音采集（输入）**：PC 端可从 Go2 EDU 内置麦克风实时录下人声，确认采样率、信噪比、与播音之间的回声影响，并能稳定送入 ASR 得到准确转写。
- **实时对话闭环**：完成“人说话 → Go2 拾音 → ASR → LLM → 讯飞流式 TTS → Go2 播报”的端到端延迟测量与稳定性验证。
- **边界与安全**：全程零运动指令，密钥零泄露，代码与记录完全与 `PLAN-0003` 解耦。
